# 用脚支撑前进：奖励修改与重训结果

本轮已完成奖励修改、重新编译、短训练、正式训练、权重加载和回放导出。最终模型明显减少了持续低姿态爬行，但不能据此保证膝盖从未触地：作者提供的物理 DLL 只有左右脚接触标志，没有膝盖接触标志。本轮使用身体高度作为姿态代理，最终动作仍需观看回放确认。

## 修改与原因

仅修改了原仓库三个受 Git 管理的文件，合计 78 行新增、4 行删除。PPO 损失、GAE、采样缓冲区、网络层结构、日志、检查点和物理 DLL 均保留。

- `src/reward_profiles.cpp`：修改 classic_100m 奖励。低姿态前进不获得距离奖励；较高姿态前进获得原有距离奖励，脚支撑时再加一份距离奖励；持续低姿态受时间罚分；增加平滑身体高度奖励，帮助模型在获得前进奖励之前学习平衡；低姿态占比过高时不获得终点奖金。影响是把优化目标从“任何方式前进”改为“较高姿态前进，并优先用脚支撑”。跨栏和跳远奖励分支未修改。
- `src/reward_profiles.h`：增加上次奖励时间、连续低姿态时间、累计罚分低姿态时间三个状态；reset 清零。这样时间罚分不依赖步数，且不会跨回合残留。
- `scripts/train_ppo.py`：增加可选的固定观测缩放。先前检查发现原模型首层约 98.9% 的输入落在 Tanh 饱和区域，策略难以根据姿态变化调整动作。缩放值跟随检查点保存、加载，旧模型仍可加载；环境输出保持原格式。没有改写 PPO 或 Actor/Critic 网络层。

新建 `configs/ppo_foot_running_v1.json`、`v2.json`、`v3.json`，用于分别保存实验设置，避免覆盖旧训练配置。该项目已有 JSON 配置系统，本轮沿用它。它们遵循作者 `.gitignore` 中私人实验配置的忽略规则，文件仍存在于本机。

项目目录旁的 `verification/evaluate_classic_policy.py` 增加姿态统计，测试文件 `verification/test_foot_reward.cpp` 验证实际 C++ 奖励。原评估/导出工具只比较通关和距离，无法判断爬行；新工具补充此指标，使用原环境、模型和回放格式。

## 最终奖励规则

身体高度比例 H = (429.8 - 躯干 y) / (429.8 + 77.05)，H >= 0.8 视为较高姿态。初始站立 H 为 1。这是代理阈值，不是膝盖碰撞检测。

每步奖励由以下部分相加：

1. 创造新的前进距离记录时，H >= 0.8 获得每米 1 分；脚支撑且 H >= 0.8 时再加每米 1 分。距离奖励上限仍为 100 米，往返移动不能重复刷分，低姿态移动也不能在之后站起时补领奖励。
2. 身体高度反馈：游戏时间增量 × (clamp(H, 0, 1) - 0.8)。站立最多每游戏秒 +0.2 分；身体更低时奖励更小或为负，超过初始站立高度不会额外获益。此项刻意帮助学习站稳，也可能使模型先站立再学习移动，需同时检查前进距离。
3. 连续低姿态超过 0.2 秒后，每游戏秒额外 -0.2 分。脚接触地面不能豁免。恢复姿态不会返还历史罚分。
4. 原有摔倒/120 秒超时 -10 保留。原有终点奖金 120 - 游戏时间保留，但累计被罚的低姿态时间超过回合时间的 10% 时，改为 -10。

物理环境结束条件没有修改。评估中的“通关”仍表示原游戏的完成标志；姿态质量另行统计，不能把通关数直接当作符合跑姿的回合数。

## 实验与结果

较弱的第一版仍允许低姿态获得前进奖励；它虽然能 64/64 通关，却几乎全程爬行。第二版取消这类前进收益后仍陷入低姿态。第三版增加平滑高度反馈，终于出现明显改善。前两版已保存作为对照，没有继续采用其爬行模型作为最终训练起点。

以下随机评估使用相同种子 20261008，每个环境只统计第一次完整回合：

| 模型 | 回合数 | 平均距离 | 低姿态时间 | 较高姿态脚支撑时间 | 平均身体高度比例 | 原游戏通关数 |
|---|---:|---:|---:|---:|---:|---:|
| 第一版 update 580，仍爬行 | 64 | 100.24 m | 98.89% | 0.82% | 0.633 | 64 |
| 第二版 update 264 | 32 | 22.03 m | 98.42% | 1.28% | 0.630 | 0 |
| 第三版 update 332 | 64 | 27.45 m | 40.65% | 32.03% | 0.820 | 0 |
| 第三版最终 update 524 | 64 | 76.17 m | 4.47% | 51.35% | 0.922 | 38 |

最终模型使用第二个随机种子 20261009 评估 32 回合：平均距离 81.50 米，低姿态 4.46%，较高姿态脚支撑 51.08%，20 回合通关。它依然存在摔倒等失败，随机策略通关率约六成，尚不能称为完全稳定。

固定选择概率最高动作的回放：100.1 米，游戏时间 75.27 秒，低姿态时间 3.76%。4 个相同确定性初始环境均通关；这些重复不代表不同初始姿态的鲁棒性验证。

## 最终训练与验证

第三版从仅做过短训练的模型出发，使用 RTX 5070 Ti：128 环境、8 个环境线程、每轮采样 256 步，512 轮，共新增 16,777,216 条转移；加上短训练累计 16,783,360 条。网络仍是共享 Tanh MLP 128/128，两个连续观测帧拼接为 136 维，离散动作 16 种。

学习率 0.0002；每轮 PPO 更新 4 epochs、8 minibatches，每个 minibatch 4096；gamma 0.995、GAE lambda 0.95、clip 0.2、entropy 0.01、value 系数 0.5。保存间隔 64 轮。本轮主要验证奖励和姿态学习，保持稳定的原 PPO 设置，仅用适中的学习率和输入缩放帮助适应新目标，没有同时进行大规模参数搜索。

通过的检查包括：实际奖励行为测试、重新编译、4 环境短训练、回合 reset、权重严格加载、原始观测 (4,68)、拼接观测 (4,136)、动作 logits (4,16)、value (4,)、环境输出和权重 NaN/Inf 检查、512 轮训练日志的损失与 KL 有限性、作者原始回放导出路径、回放 CRC 与动作 0..15 检查。

最终轮 policy loss 0.0056，value loss 0.5215，KL 0.00367。512 轮 value loss 范围 0.0007..1.304，未发现 NaN/Inf。训练正常结束并保存最终模型，不是中途终止的临时检查点。

最终正式训练约 4 分 40 秒。本次从奖励调整到全部试训、编译、评估和结果整理总计约 45 分钟，其中包括效果不佳的前两版试验。
