# 100 米低于 50 秒的本地训练记录

## 成绩来源

PPO 训练的最佳保存点为 `checkpoints/ppo_start50_v16_policy_update_005920.pt`，默认初始条件下，确定性动作完成比赛用时 50.166668 秒。

在该保存点上对 Actor 动作偏置进行 512 个候选的局部搜索，随机种子为 81601，得到 49.966667 秒的最终权重。最终模型包含 PPO 训练与搜索两部分成果，并非未经修改的 PPO 保存点。搜索是在项目目录外层的本地验证脚本中完成；该辅助脚本未纳入此提交。

交付文件为 `checkpoints/ppo_classic100m_under50.pt`，回放为 `replays/classic_100m_under50_49p97.bin`。交付权重中的优化器已重新初始化，避免续训使用偏置搜索前的动量。权重、回放、构建产物和日志按原忽略规则保存在本地，本 Git 提交不包含这些二进制成果。

## 本轮改进

- **起步奖励**：首次到达 10 米时最高额外 40 分，5.5 秒以内取满分，7.5 秒及以后为 0。前 10 米另给予每米最多 4 分的连续奖励，5.5 秒后逐渐减少，9 秒后为 0。只奖励新前进距离，保持低姿态约束，避免往返刷分或重复领取。
- **动作选择**：从较快候选继续训练前，提高动作分布集中程度，减少随机动作扰乱已有步态；之后继续 PPO 训练，而不是仅保存候选。
- **GAE**：lambda 从 0.95 提高到 0.98，用意是让迈步动作获得更长范围的反馈；该单独试验没有刷新纪录。
- **价值损失**：系数从 0.5 降到 0.05，用意是减少价值回归对 Actor/Critic 共享特征的影响。该续训轮获得了 50.17 秒的 PPO 保存点。
- **KL 停止条件**：新增可选 `target_kl`，默认关闭；本次设为 0.015。超过阈值时停止当前采样批次的后续优化，再采集新数据。该机制不保证每个批次测得的 KL 都小于阈值，单独试验也没有刷新纪录。
- **最后的局部搜索**：微调动作偏置，将 50.17 秒降到 49.97 秒，取得确定性成绩低于 50 秒的结果。

这些结果来自逐轮训练、候选搜索及保存点筛选，未做完整消融实验，不能将所有提升归功于单个奖励项或参数。物理后端、赛道、成功条件和游戏计时均保持作者原实现。

## 配置

最终 PPO 训练配置保存于 `configs/ppo_start50_v16_policy.json`；后续续训配置为 `configs/ppo_under50_resume.json`。这是从原忽略规则中显式纳入 Git 的两个最终配置，其他实验配置仍保持本地。

主要参数为 128 个环境、8 个线程、256 步 rollout、4 个优化 epoch、8 个 minibatch、学习率 5e-5、gamma 0.995、GAE lambda 0.98、clip 0.2、熵系数 0.02、价值损失系数 0.05、target KL 0.015、8 帧观测历史、128×128 隐藏层。保留原 PPO、网络、buffer、日志和 checkpoint 架构。

两个配置的 `resume_from` 均引用本地权重；只检出 Git 提交不会自动获得这些权重。没有本地成果时不能按该配置直接复现续训。
